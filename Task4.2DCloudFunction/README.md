# 4.2D Calling Functions from the Web

## Project Summary
A small web UI lets a carer toggle room lights; the UI posts {room, action} to a backend endpoint. The backend validates and forwards the command to an Arduino device that runs a local HTTP server. The Arduino sketch parses room:action, maps room names to GPIO pins, and drives LEDs/relays. The system is intended as a simple, local-control proof‑of‑concept with optional cloud sync.

---

## Hardware used
- **Board:** Arduino Nano 33 IoT
- **Outputs:** LEDs (or relay modules) to represent lights
- **Other:** Breadboard, jumper wires, resistors for LEDs, USB cable, optional external power for relays

## Wiring summary
- **Living Room LED:** - PIN_LIVING -> D6
- **Bathroom Room LED:** - PIN_BATH -> D3
- **Closet LED:** - PIN_CLOST -> D4

## How to run
1. Arduino sketch
- Open CloudAndLocalHTTP_Fixed.ino in the Arduino IDE.
- Ensure thingProperties.h exists (generated by Arduino IoT Cloud).
- Select the correct board (e.g., Nano 33 IoT) and port, then compile and upload.
  
2. Backend / Node-RED
- Deploy a small HTTP endpoint that accepts POST /api/command (or change ENDPOINT_URL in app.js to match).
- The backend should validate the Authorization header and forward {room, action} to the Arduino.

3. Web UI
- Serve index.html (static file) from any simple web server or open locally.
- Edit app.js and set ENDPOINT_URL and API_KEY to match your backend.
- Open the page in a browser, toggle a room checkbox and observe the LED and Serial Monitor.

4. Open Serial Monitor at 115200 to observe sensor readings and ThingSpeak responses; the sketch writes to ThingSpeak every 30 seconds.

## Code overview — what each part does
1. **4.2DCallingFunctionsFromWeb.ino:**
- Pin definitions & setupPins() — defines PIN_LIVING, PIN_BATH, PIN_CLOSET and configures them as outputs, initialized LOW.
- Local HTTP server (handleLocalHttp()) — listens on port 8080 for GET /ping, GET /toggle, and POST /command. POST /command accepts JSON { "room":"...", "action":"on"}, parses it, and sets cloudCommand to room:action.
- Cloud sync & parsing (handleCloudCommand()) — parses cloudCommand strings of the form room, room:action, or room:action and forwards to toggleRoom().
- Action execution (toggleRoom()) — maps room names to pins via roomToPin(), writes HIGH/LOW for on/off, toggles for toggle.
- Main loop — calls ArduinoCloud.update(), checks for timer expiry to turn pins off, and calls handleLocalHttp() to serve requests.
- JSON helpers — extractJsonString() and extractJsonInt() are simple, tolerant parsers used for the small, predictable payloads.

2. **app.js:** 
- Configuration — ENDPOINT_URL and API_KEY define where the UI posts commands.
- sendCommand(room, action) — builds payload {room, action} and POSTs to the backend; returns success/error.
- DOM wiring — on DOMContentLoaded each input.toggle is wired to a debounced change handler that calls sendCommand.
- UI helpers — setGlobalStatus() and setRoomStatus() update status text on the page.

3. **index.html and styles.css:** Minimal UI with labeled toggles for each room; CSS provides a clean, responsive layout.


## Testing checklist
- Confirm pin mapping in 4.2DCallingFunctionsFromWeb.ino matches the physical wiring (D6, D3, D4).
- Verify the Arduino connects to Wi‑Fi (if using cloud features) and prints an IP address to Serial.
- From the browser UI, toggle a room and confirm the backend receives a POST with {room, action}.
- Confirm the backend validates the Authorization header and forwards the command to the Arduino.
- On the Arduino Serial Monitor, confirm you see New cloudCommand: ... and Set pin X HIGH/LOW messages when toggling.
- Confirm the LED or relay changes state when the command is sent.
